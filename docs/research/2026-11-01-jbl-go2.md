# JBL GO 2 connection experiment — 2026-11-01

Historical first experiment. The [follow-up writing utility](2026-11-01-speaker-config-writing.md)
supersedes the temporary-image state below: Jeff now reads GO 2 from SD, the
compile-time override is removed, and Cam heard startup speech and Polo clearly.

## Problem and bounded research

Classic Bluetooth discovery, security pairing and A2DP media negotiation are
separate asynchronous stages. An absent first-result name does not prove an
incompatible speaker. Identify the failed stage before changing radio policy.

- [Espressif Classic GAP API](https://docs.espressif.com/projects/esp-idf/en/v5.4/esp32/api-reference/bluetooth/esp_gap_bt.html):
  discovery includes inquiry and name discovery. Missing EIR names may be
  resolved later by the stack. The linked version is 5.4; inspect the installed
  5.5.4 implementation before assuming a version-specific name-resolution fix.
- [Espressif A2DP API, release 5.5](https://docs.espressif.com/projects/esp-idf/en/release-v5.5/esp32/api-reference/bluetooth/esp_a2dp.html):
  connect to the sink address after source initialization and inspect asynchronous
  connection/media results.
- [JBL GO 2 manual](https://jp.jbl.com/on/demandware.static/-/Sites-masterCatalog_Harman/default/dw5193d0bc/pdfs/JBL_GO2_Instruction-Manual_JAPANESE.pdf):
  Bluetooth button enters pairing mode; legacy PIN is 0000 if requested.
- [JBL GO 2 specifications](https://www.jbl.com/on/demandware.static/-/Sites-masterCatalog_Harman/default/dw26d91c33/pdfs/JBL_GO2_Spec_Sheet_English.pdf):
  A2DP sink support makes a Classic ESP32 source a plausible compatible source.
  Specifications alone do not demonstrate this unit working.

Decision: first select the requested speaker, retain exact-name selection and
existing PIN/SSP behavior, then observe discovery, authentication, negotiated
codec and PCM. Do not add retries or codec workarounds without evidence.

Installed 5.5.4 `esp_gap_bt_api.h` lines 636–640 explicitly confirms discovery
produces `ESP_BT_GAP_DISC_RES_EVT` for both inquiry and subsequent name discovery.
Current code consumes those results and waits for discovery stop; no extra
remote-name operation is justified before a local discovery failure is observed.

## Live result

After Cam renewed pairing mode, inquiry saw an unnamed result and then the exact
`JBL GO 2` name at the same address (2c:fd:b4:eb:84:a7). This locally demonstrates
the existing two-stage name discovery works; no name-resolution workaround needed.
At uptime 128.050 s the exact candidate was selected; authentication status 0
at 130.800 s, A2DP connected at 130.870 s, media start success at 130.950 s.
SBC raw 21:15:02:35, 44.1 kHz stereo, bitpool 2..53. Startup PCM completed at
134.900 s. Status at 136.290 s: speaker=1, stream=1, dropped=0, fault=0.

No radio/security/codec change was required for this first successful software
connection. The physical pairing window and selecting GO 2 rather than Flip 6
were sufficient in this experiment. The historical Arduino failure was not
reproduced or diagnosed. Acoustic confirmation and power-cycle recovery remain
separate from the successful connection/PCM-delivery telemetry.

At the end of the first experiment Jeff ran the explicit test image selecting
GO 2; SD config still selected Flip 6. No Anthony or Death image was changed.
Changes were local/uncommitted at that stage. Saved artifacts make the original
experiment and return to the verified previous application reviewable.

## Acoustic confirmation

Cam reported no audible initial startup announcement despite completed source
PCM. Keep that negative observation: cold-start speech readiness is unresolved.
Do not call the initial startup acoustically successful or assume a cause.

Explicit serial `tone` was accepted at 156.010 s and Cam heard it. Next,
`play /audio/Polo.wav` was accepted at 165.310 s, played at 165.440 s and
completed at 166.000 s: 24,289 frames, zero underruns. Cam reported “I heard
Polo” and confirmed clear speech through GO 2. Status after playback:
speaker=1, stream=1, dropped=0, fault=0, SD mounted, actuator stuck=0.
This establishes an audible live connection and SD speech playback; sustained
show playback, power-cycle reconnection and first-announcement timing remain
unqualified. Leave the selected experimental image running for Cam's experiment.
