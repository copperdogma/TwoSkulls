# Native Anthony jaw/eye bench extension — 2026-10-15

Cam wired servo signal to GPIO23 with separate 5 V/common ground, and eyes to
GPIO32/33/shared ground retaining the documented resistor. The previous native
image intentionally had no output driver. This extension enables those outputs
and startup announcement animation; it does not port full skits or Jeff control.

## Implementation and source decisions

The checked-in old app hardcodes jaw limits 0–80 degrees, despite exposing getters
named as configuration. Its actual installed `Servo.h` is from
`ESP32_ESP32S2_AnalogWrite`, whose `pwmWrite` defaults are 544–2400 us for 0–180°.
Preserve this mapping: 80° is about 1368 us, not 2400 us. The first commentary's
reference to saved jaw limits was corrected after source inspection.

[ESP-IDF 5.5.4 LEDC documentation](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32/api-reference/peripherals/ledc.html)
requires timer/channel configuration and duty-update calls. Adopt separate
low-speed APB timers: timer0 50 Hz/16-bit for servo channel0; timer1 5 kHz/8-bit
for eye channels1/2. GPIO23/32/33 do not overlap the onboard SD signals.

Initial outputs are jaw closed and eyes100/255. The existing diagnostic task
runs a gated 20 ms control tick, with a nonblocking 0→30→0 degree boot check over
1.2 seconds. Its clock begins on the first control tick, after Matter readiness,
so initialization delays do not skip it. Serial `jaw-test` can repeat the check
when startup is idle. Speech cancels the check and takes priority.

Startup loading now also precomputes 20 ms RMS windows in PSRAM from the gained
PCM. Callback work adds only an atomic consumed-frame cursor store; the control
task reads the corresponding immutable envelope, applies legacy amplitude .1 /
gain5 / clamp15000 / threshold1000 / jaw .2 smoothing, and drives outputs. Eyes
brighten to255 during startup speech and return to100 afterward. Jaw closes when
startup is finished or interrupted. The quiet diagnostic tone is not animated.
No new task, callback-time DSP/SD access/PWM work or card writes were introduced.

The cursor tracks delivered source PCM, not acoustic playback. JBL buffering can
make jaw motion lead the sound; owner timing assessment is still needed. Legacy
constants now run on a fixed 20 ms control cadence, so similar responsiveness is
intended but identical old callback-dependent motion is not claimed.

## Software checks

Independent source review found no blocking defect in RMS arithmetic, window
bounds, publication, PWM ownership, timer separation or pulse mapping. Host tests
compile the actual production driver with LEDC/time stubs and pass under address
and undefined-behavior sanitizers plus warnings as errors. They verify routing,
initial pulse, first-tick timing, 20 ms gate, gentle check, speech takeover,
brightness, closing and bounded travel under high RMS input.

```sh
c++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined \
  -Iscripts/tests/actuator_stubs -Ifirmware/main \
  scripts/tests/test_skull_actuators.cpp firmware/main/skull_actuators.cpp \
  -o /tmp/twoskulls-actuator-tests
/tmp/twoskulls-actuator-tests
```

These are command-level checks; physical movement, eye light, power stability and
sound/motion alignment require hardware observation. Build/upload/live results
follow below when observed. Full peer/resource/show acceptance remains open.

Final ESP-IDF build succeeded: 2,078,240-byte binary, static DRAM99,012 bytes,
IRAM130,079 bytes (993 remaining). The narrow static IRAM budget remains a full
application port concern. Recorded source/binary/ELF SHA-256 manifest is ignored
`build/validation/2026-10-15-actuators-build-hashes.json`. Expected prototype MAC
`a0:a3:b3:80:16:38` was reverified before the authorized app-only flash at0x30000;
NVS and the partition table are preserved. Runtime results follow.
